### 2. Interactive visualization dashboard (`logistic_visualization.ipynb`)
Generated by `build_logistic_viz_notebook.py` (a generator script, like the module builder).
Dashboard = Plotly `FigureWidget`s + ipywidgets console. Features added incrementally:
- **Two figures** (log-loss, zero-one), each with train/valid/test traces.
- **6 show/hide checkboxes** (metric × split) — display-only, instant, never recompute.
- **Params inputs** `n,d,k,eta,seed,steps,valid_size,test_size`; `parse_int` accepts `1e4`, `1.5e3`, `10k`.
- **Wrapping layout** (`flex_flow="row wrap"`) so figures stack when the window is narrow.
- **X/Y linear|log toggle pairs** (green = selected) copied from `sonnet_visualization`.
- **Parameter memory** — `last_params.json` saved on each Run; inputs initialize from it on open.
- **Past-runs dropdown** — backed by lightweight `logistic_cache/index.json`; select a run to load
  its params + step count, then bump `steps` and Run to extend. Auto-refreshes after each run.
- **Early-stopping vertical lines** (toggleable, on both figures):
  - **oracle stop** (green dashed) — first step where train log-loss ≤ `L̂(w*)`.
  - **validation argmin** (purple dashed) — argmin of validation log-loss (skips t=0).

### 3. pkl cache with resume/extend
- Cache key = **setup only** (`n,d,k,eta,seed,valid_size,test_size`), NOT `steps`.
- Each pkl stores `{setup, steps, trajectories, data (X/y train/valid/test), w_last_iterate, oracle_threshold}`.
  Data is stored (not regenerated) per Ali's request.
- Run behavior: new setup → compute; `steps ≤ cached` → return cached; `steps > cached` → **resume
  from `w_last_iterate` on stored data for the extra Δ steps and append**.
- Verified headlessly that **extend == from-scratch** exactly (GD is deterministic; the loop records
  loss before stepping, so the last iterate was never recorded → resume stitches with no gap/dup).
