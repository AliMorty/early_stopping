### Interactive dashboard — design discussion

Agreed on the following design:

#### File naming and storage
- New filename format: `run_n{n}_d{d}_k{k}_seed{seed}_T{T}_{timestamp}.pkl`
- Store `X` and `y` in the pkl (the only random parts of the algorithm — generated from seed in `generate_data()`)
- Two run modes: **scratch** (always creates new file, even if one exists) and **resume** (loads existing pkl, continues GD, saves new file with updated T — old file preserved)

#### Dashboard design
- Sliders for `n`, `d`, `k`, `seed`, `T` — each slider only shows values where matching pkl files exist with all other params fixed
- Sliders update dynamically when you move to a new state
- Radio buttons to select which metric to view (norm, loss, angle to w*, angle to w̃)
- Two side-by-side plots: **current** | **previous**
- Previous updates on every slider move (previous ← current before moving)
- Initial state: smallest `(n, d, k)` available
