### Architecture

   ```bash
   jupyter nbconvert --to script ali_code/logistic_regression_hold_out.ipynb --output ali_code/logistic_regression
   ```
   Then wrap experiment cells in `if __name__ == "__main__":` so they don't run on import.

2. New visualization notebook (like `sonnet_visualization` for linear regression) that:
   - Imports `LogisticRegressionClass` from `logistic_regression.py`
   - Has a params cell: `n, d, k, eta, seed, number_of_steps`, etc.
   - Uses a **hash-based pkl naming scheme** for caching:
     ```python
     key = hashlib.md5(json.dumps(config, sort_keys=True).encode()).hexdigest()[:8]
     filename = f"logistic_{key}.pkl"
     ```
   - If pkl exists → load; otherwise run GD, save pkl, then plot
   - pkl stores trajectories + full config (not X/y, since those are regeneratable from seed)

### Why hash-based naming
- Flat filename like `n100_d200_k10_eta0.1_seed85.pkl` breaks when new parameters are added
- Hash automatically adapts to any config dict — just add new keys and old pkls remain valid
- Full config stored inside pkl so files are always inspectable
