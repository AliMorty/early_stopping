## Why vector matters (discussion)
- A PNG screenshot is fixed-resolution pixels → blurry when scaled up in a two-column paper.
  Vector (PDF/SVG) stores draw instructions → razor-sharp at any zoom, crisp text.
- Verified the reference paper is 100% vector: `pdfimages -list early_stopping_logistic_regression.pdf`
  returns **zero** embedded raster images. Its figures were built by arXiv `tex2pdf` from
  per-figure PDFs (matplotlib `savefig`).
- "Many iterations" is NOT a problem for vector: a risk-vs-iteration curve is ONE path object
  with many vertices (tiny, cheap). Bloat only comes from **markers/scatter dots**, each its
  own shape. The region plots use ~50 ticks per trajectory → cheap.

## Tooling
- Export engine: **`kaleido`**. Plotly 6.x pip-installs kaleido **v1.3.0, which now requires a

  warning; still fully functional.

## Critical catch — Scattergl exports as raster
- The region plot draws every trace with **`go.Scattergl` (WebGL)** for responsiveness with
  100k-point paths. **Scattergl traces export to PDF/SVG as an embedded raster bitmap**, so a
  naive `write_image` would still be pixelated — defeating the whole point.
- Fix baked into the export helper: `_to_vector_figure(fig)` rebuilds each Scattergl trace as
  **`go.Scatter` (SVG)** (identical schema) before writing. Display keeps using Scattergl.
- Verified: region plot (Scattergl) → exported PDF has **0 raster images** (fully vector);
  raw un-converted Scattergl PDF contained 1400×1000 bitmaps. Over-time plots already use
  `go.Scatter` (vector-native).
