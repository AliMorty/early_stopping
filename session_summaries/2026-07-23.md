## What Was Done

### 1. `proj_on_2d_subspace(self, vectors, v1, v2)` in the notebook (Ali wrote it)
- Orthonormalizes the plane internally via Gram–Schmidt: `u1 = v1/‖v1‖`,
  `u2 = (v2 − ⟨v2,u1⟩u1)` normalized, returns `np.stack([W@u1, W@u2], axis=-1)`.
- Debugged together: correct Gram–Schmidt denominator is `‖b‖²` (his `‖b‖¹` only works after
  normalizing); fixed a `u2 = u2/…` typo (should be `v2_prep`); `axis=-1` (not `axis=1`) so it is
  shape-agnostic: `(d,)→(2,)`, `(T,d)→(T,2)`, `(n_traj,T,d)→(n_traj,T,2)`.
- Return shape choice: the stacked `(...,2)` array (PCA-`.transform` convention) over a 2-tuple.
- Vectorized both v1 and v2 to call it once on the whole `(n_traj,T,d)` stack instead of looping
  (valid because trajectories share length).

### 2. Bug found: `w*` was landing off the x-axis (nonzero y = ε)
- **Cause:** the two plot axes (`w* dir`, `Σw̃ dir`) are **not orthogonal**, so in that oblique
  frame a point on the x-axis leaks into y. `w*` genuinely has a component along the raw `Σw̃`
  axis because each `w̃ᵢ` (max-margin direction) correlates with `w*`.
- **Deeper issue:** after Ali added the orthonormalizing `proj_on_2d_subspace`, the **trajectories**
  used the corrected orthonormal frame, but the **reference points** (`w*`, `w̃`) were still
  projected in `region_visualization.ipynb` via raw dot products (`w_star @ w1`, `w_star @ w2`) —
  a *different* (oblique) frame. So `w*` still showed ε and was inconsistent with the trajectories.
